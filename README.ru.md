# Game Dev Skills для Claude Code — Unreal Engine 5.8

Agent Skills, после которых [Claude Code](https://claude.com/claude-code) реально полезен на проекте на Unreal, а не уверенно ошибается.

Семь скилов: сеть, свет, ассеты, оптимизация, UI, встроенный в движок MCP-сервер и генерация 3D через AI. Написаны под **UE 5.8** и сверены с сорцами 5.8.1 — а не вытащены из памяти модели.

## Зачем это

Спросите любую LLM про cvar в Unreal — получите правдоподобное имя, которого может не существовать. Два примера, найденных прямо при написании этих скилов:

| Что говорит модель / документация | Что реально в UE 5.8.1 |
|---|---|
| `r.MegaLights.Allow` (страница документации самой Epic) | `r.MegaLights.Allowed`, плюс `r.MegaLights.EnableForProject` и `r.MegaLights.Supported`, которых в доке нет вообще |
| `bUseIris = true;` в `*.Target.cs` (кочует по блогам и AI-ответам) | **не существует** в UnrealBuildTool 5.8. Iris включается через `net.Iris.UseIrisReplication` + `FIrisNetDriverConfig` |

Поэтому каждый скил начинается с одного правила: **сверяй с сорцами того движка, под который реально собираешься, прежде чем что-то утверждать.** В каждом скиле лежат готовые команды `grep` и инструкция, как найти сорцы движка по `.uproject`.

Остальное — то, чего нет в доке в одном месте: деревья решений, порядок «что резать первым», таблицы «симптом → причина» и те грабли, на которые уходят недели.

## Скилы

| Скил | Что покрывает | Когда срабатывает |
|---|---|---|
| **`ue-networking`** | Репликация (generic + Iris), Push Model, RPC, сабобъекты, релевантность/dormancy, трафик, `-NetTrace` | Любое реплицируемое свойство. «В PIE работает, на dedicated — нет». Выбор Iris vs generic |
| **`ue-lighting`** | Lumen + **Lumen Lite**, MegaLights, Virtual Shadow Maps, Substrate, RT-сцена, уровни качества | Настройка света, бюджет GPU, шум/протечки/мерцание, качество по платформам |
| **`ue-assets`** | Импорт (Interchange/FBX/glTF), Nanite (static/skeletal/foliage/assemblies), коллизии, UV, текстуры, инстансинг, HLOD | Импорт мешей, Nanite или LOD, кривые коллизии и масштаб, память мешей/текстур |
| **`ue-performance`** | `stat unit` → узкое место, Unreal Insights, GPU Visualizer, PSO precaching, стоимость тика и блюпринтов, GC, стриминг | Всё, что тормозит или дёргается. Бюджет кадра. Перед тем как заявить, что оптимизация сработала |
| **`ue-ui`** | UMG + Slate, CommonUI, **Unified Input System** из 5.8, фокус и навигация геймпадом, DPI и safe zones, производительность виджетов | HUD/меню, UI под геймпад, баги фокуса, UI ест кадр |
| **`ue-mcp`** | Встроенный в 5.8 **Unreal MCP** — установка, 27 тулсетов, tool search, свои тулы на C++/Python, безопасность | Подключение агента к живому редактору. Свои MCP-тулы под проект |
| **`meshy-3d-generation`** | API [Meshy AI](https://meshy.ai) — text/image→3D, текстуры, риг, анимация | Генерация 3D-ассетов. В паре с `ue-assets` — чистка перед импортом |

`ue-mcp` — тот, который меняет остальные: с подключённым редактором агент видит живое дерево Slate, читает свойства акторов и гоняет автотесты, вместо того чтобы додумывать по `.uasset`, которые он всё равно не прочитает.

Каждый UE-скил — это `SKILL.md` плюс справочники, которые подгружаются только когда нужны: таблицы cvar, кукбуки, чек-листы.

### Что именно поменялось в 5.8

Скилы актуальны по дельте 5.8, а не советуют как в 5.3:

- **Встроенный MCP-сервер** — `Engine/Plugins/Experimental/ModelContextProtocol`, от Epic, экспериментальный, по умолчанию выключен. Агенты рулят редактором через `http://127.0.0.1:8000/mcp`
- **Iris стал production-ready** (был Experimental по 5.7 включительно) — с настоящим способом включения, а не блогерским
- **Lumen Lite** — новый уровень GI Medium, примерно вдвое быстрее high, цель 60 fps на PS5 и хендхелдах. **SSGI объявлен deprecated** в его пользу
- **MegaLights production-ready** — сильно меньше шума, ранний кулинг по мощности источника
- **Unified Input System** — Enhanced Input и Common Input/UI объединены, дублирующие дата-ассеты больше не нужны
- **Nanite Foliage / Assemblies**, Nanite Pixel Programmable Distance, управление WPO для скиннед-мешей
- **Snapshot hitches**, Spatial Profiler, счётчик UObject Count в Insights
- MallocBinned3 по умолчанию на Windows, memory-mapped asset registry, инкрементальный GC с учётом акторов
- Мобилки: multi-pass deferred по умолчанию

## Установка

**Нужен** [Claude Code](https://claude.com/claude-code). UE-скилам больше ничего не требуется. Для `meshy-3d-generation` нужен Python 3 с `requests` и ключ API Meshy.

### Вариант A — на уровне пользователя (во всех проектах)

```powershell
# Windows
git clone https://github.com/Schepetkov/claude-skills-game-UE.git
cd claude-skills-game-UE
.\install.ps1
```

```bash
# macOS / Linux
git clone https://github.com/Schepetkov/claude-skills-game-UE.git
cd claude-skills-game-UE
./install.sh
```

Скрипт линкует скилы в `~/.claude/skills/`. На Windows — через directory junction (права админа не нужны), на POSIX — симлинками. Поэтому `git pull` в этой репе обновляет скилы сразу везде. Флаг `-Copy` / `--copy` — если нужны независимые копии.

### Вариант B — только в один проект

```bash
# из корня UE-проекта
cp -r /path/to/claude-skills-game-UE/skills/ue-lighting .claude/skills/
```

### Вариант C — выборочно

```powershell
.\install.ps1 -Skills ue-networking,ue-performance
```

```bash
./install.sh ue-networking ue-performance
```

Проверить — командой `/skills` в Claude Code.

## Как пользоваться

Скилы подхватываются сами, когда разговор попадает под их описание. Можно и вызвать явно:

```
/ue-performance переход хода дёргается, разберись почему
```

Примеры запросов, которые их включают:

- *«Почему реплицируемое свойство не обновляется на клиенте?»* → `ue-networking`
- *«Lumen жрёт 8 мс, что резать первым?»* → `ue-lighting`
- *«Этому мешу нужен Nanite?»* → `ue-assets`
- *«Игра дёргается, когда первый раз спавнится новый тип врага»* → `ue-performance` (PSO precaching)
- *«Геймпадом не добраться до меню настроек»* → `ue-ui`

## Что скилы делают и чего не делают

**Делают:**
- Заставляют сначала измерить, и не дают назвать проблему решённой без «до/после»
- Дают дерево решений с конкретной рекомендацией, а не обзор вариантов
- Называют самый дешёвый фикс первым и говорят, чем каждый оплачивается
- Помечают экспериментальные фичи как экспериментальные (Mesh Terrain, нативный Nanite RT, prefiltered distant VSM)
- Отправляют в сорцы движка вместо утверждений по памяти

**Не делают:**
- Не гарантируют имя cvar, если у вас нет дерева сорцов для проверки. На Launcher-сборке скилы переключаются на проверку в рантайме (`DumpConsoleCommands`, автодополнение консоли) и явно говорят, каким способом проверяли
- Не разбирают Blueprint-only пайплайны в глубину — уклон в C++ с блюпринтами на листьях
- Не покрывают анимацию, звук, физику и Sequencer. PR приветствуются

## Версия движка

Написано и проверено под **UE 5.8 / 5.8.1**.

Бóльшая часть верна для 5.5+, специфика 5.8 помечена отдельно. Всё, что Epic переименует, устареет — ровно поэтому каждый скил начинается с «сначала grep по сорцам», а не с просьбы верить таблице.

На другой версии скилы тоже работают: методология, деревья решений и таблицы симптомов от версии не зависят. Проверять нужно только имена cvar — и скилы прямо велят агенту это делать.
